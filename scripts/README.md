# @blrhikes/scripts

Data-migration scripts that pull trail content out of the GitHub issues in
[`shreshthmohan/blrhikes-data`](https://github.com/shreshthmohan/blrhikes-data)
and seed it into PayloadCMS.

## Refreshing the cache (getting the latest data)

The scripts cache GitHub data locally so repeated runs don't hammer the API:

| Path | What it is |
| --- | --- |
| `.cache/github-data.json` | Raw issues + comment threads, with a `fetchedAt` timestamp |
| `.cache/source/*.md` | One markdown file per issue, rendered from the cache |

When this cache is stale, refresh it from the repo root:

```bash
pnpm pull   # or the shorthand: pnpm p
```

This is `pnpm --filter @blrhikes/scripts seed:sections -- --refresh`. It:

- re-fetches all `trail` + `status:live` issues (and their comments) from GitHub,
- rewrites `.cache/github-data.json` and `.cache/source/*.md`,
- then **stops** — it is refresh-only, makes no CMS writes, and does not
  require `CMS_API_KEY`.

To re-run against the CMS afterwards, invoke the port phase separately (below).

> Note: `.cache/target/` is **not** regenerated by these scripts — it holds
> older manual/port artifacts and is safe to ignore when refreshing.

### Rate limits

Unauthenticated GitHub requests are capped at 60/hr. Set `GITHUB_TOKEN` in
`scripts/.env` to bump that to 5000/hr (see `.env.example`).

## Setup

Copy the env template and fill it in:

```bash
cp scripts/.env.example scripts/.env
```

- `CMS_URL` — PayloadCMS instance (default `http://localhost:3000`)
- `CMS_API_KEY` — API-key auth (`Authorization: users API-Key <key>`); required
  for any CMS write, not for `pnpm pull`
- `GITHUB_TOKEN` — optional, raises the GitHub rate limit

## Commands (run from repo root)

| Command | Underlying | Does |
| --- | --- | --- |
| `pnpm pull` | `seed:sections -- --refresh` | Refresh the GitHub cache only (no CMS writes) |
| `pnpm seed` | `migrate.ts` | Seed trails into the CMS from the cache (skips existing) |
| `pnpm seed:refresh` | `migrate.ts -- --refresh` | Refresh cache **and** seed the CMS (needs `CMS_API_KEY`) |
| `pnpm seed:gpx` | `migrate-gpx.ts` | Seed GPX tracks |
| `pnpm sections` | `seed:sections` | Dry-run port of content sections into the CMS |
| `pnpm sections:write` | `seed:sections -- --commit` | Same, but writes to the CMS |

`migrate.ts` also accepts `--force` to update trails that already exist in the
CMS (default behaviour skips them).
